Project: Persistent AI + Human Support Chat (Ticket-Based, Same History)

🎯 GOAL

Build an in-house support chat system for Arapint that:

Keeps one continuous chat history while a ticket is OPEN

Supports AI-first replies, then human agents

Allows users to return later and continue the same conversation

Does NOT use third-party platforms (no Zendesk, Intercom, etc.)

1️⃣ CORE CONCEPT

One Ticket = One Conversation Thread

Every support request must have:

ticket_id

conversation_id (never changes while ticket is open)

All messages (user, AI, agent) append to the same conversation.

2️⃣ SYSTEM ARCHITECTURE
Backend Stack (Recommended)

API: FastAPI or Node.js (Express/Nest)

DB: PostgreSQL

Cache / Queue: Redis

Realtime: WebSocket

AI: OpenAI-compatible LLM (context-based)

Auth: JWT (user & agent roles)

3️⃣ DATABASE SCHEMA (MANDATORY)
tickets
id (uuid, pk)
user_id
status (open | pending | resolved | closed)
priority
assigned_agent_id (nullable)
created_at
updated_at

conversations
id (uuid, pk)
ticket_id (fk)
last_message_at
summary (text, auto-generated by AI)

messages
id (uuid, pk)
conversation_id (fk)
sender_type (user | ai | agent | system)
sender_id (nullable)
content (text)
created_at

internal_notes (agents only)
id
ticket_id
agent_id
note
created_at

4️⃣ CHAT FLOW LOGIC
Step 1: User Starts Chat

Check for existing OPEN ticket

If exists → reuse conversation_id

If not → create new ticket + conversation

Step 2: AI Responds First

AI must:

Load full conversation history

Respond in same conversation

Set confidence score

Decide:

resolve

ask clarification

escalate to agent

Step 3: Agent Takes Over (If Needed)

Agent sees:

full history

AI summary

AI suggested reply

Agent replies in same conversation

Step 4: User Returns Later

If ticket is OPEN → continue same chat

AI reads full history and resumes naturally

5️⃣ AI MEMORY HANDLING (CRITICAL)

AI input must include:

{
  "system": "You are Arapint Support AI",
  "conversation_summary": "...",
  "recent_messages": [...last 20],
  "user_profile": {...},
  "ticket_status": "open"
}


If conversation is long:

Auto-summarize old messages

Store summary in conversations.summary

6️⃣ ESCALATION RULES

AI must escalate if:

confidence < 0.75

user says “agent”, “human”, “complaint”

repeated failure

sensitive topics (billing, verification, fraud)

Escalation action:

Tag ticket

Assign agent

Add internal note

7️⃣ REAL-TIME CHAT REQUIREMENTS

Frontend must:

Use WebSocket

Bind messages to conversation_id

Show sender identity (AI / Agent)

Preserve message order

Load previous messages on reconnect

8️⃣ AGENT DASHBOARD (MINIMUM FEATURES)

Agents must have:

Ticket list (filters: open, urgent, assigned)

Full chat history

Internal notes

AI summary panel

Reply + close ticket

9️⃣ SECURITY & LOGGING

Messages immutable

Full audit logs

Role-based access

Mask sensitive data

Store AI decisions

🔟 SUCCESS CRITERIA

System is complete when:

User never repeats themselves

AI + agent feel like one entity

Same chat continues across days

Zero third-party dependency
